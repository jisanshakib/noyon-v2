# Binance Agentic TG Bot

A public Telegram bot that automates BSC (BNB Smart Chain) token minting and selling via a Binance Agentic Wallet, with Gemini AI handling natural-language intent routing.

---

## Folder Structure

```
binance-agentic-tg-bot/
├── src/
│   ├── config.ts              # Env validation & typed config
│   ├── logger.ts              # Pino structured logger

│   ├── gemini.ts              # Gemini AI intent router + summary generator
```

## Environment Variables

Copy `.env.example` to `.env` and fill in every value before running locally.

| Variable | Required | Description |
|---|---|---|
| `GEMINI_API_KEY` | ✅ | Google AI Studio API key — [get one here](https://aistudio.google.com/app/apikey) |
| `TELEGRAM_BOT_TOKEN` | ✅ | Telegram bot token from [@BotFather](https://t.me/BotFather) |
| `SUPABASE_DB_URL` | ✅ | PostgreSQL connection string from your Supabase project → Settings → Database |
| `ADMIN_ID` | ✅ | Your Telegram numeric user ID (message [@userinfobot](https://t.me/userinfobot) to find it) |
| `BSC_RPC_URL` | ✅ | BSC mainnet RPC — public: `https://bsc-dataseed1.binance.org/` or private via [NodeReal](https://nodereal.io/) / [Chainstack](https://chainstack.com/) |
| `SUPABASE_URL` | ☑️ Optional | Supabase REST API base URL (future extensions) |
| `SUPABASE_SERVICE_ROLE_KEY` | ☑️ Optional | Supabase service role key (future extensions) |
| `BINANCE_WALLET_PAIRING_BASE_URL` | ☑️ Optional | Deep-link base for Binance Wallet pairing. Defaults to `https://app.binance.com/en/wc?uri=` |
| `LOG_LEVEL` | ☑️ Optional | Logging verbosity: `trace` / `debug` / `info` / `warn` / `error`. Defaults to `info` |
| `PORT` | ☑️ Optional | HTTP health-check port. Defaults to `3000` (Railway sets this automatically) |

> ⚠️ **Never commit `.env` to Git.** It is listed in `.gitignore`. Only `.env.example` (with no real values) belongs in the repository.

## Local Setup

### Prerequisites

- Node.js ≥ 18 (`node --version`)
- A Supabase project (free tier works) or any PostgreSQL 14+ instance
- All five required environment variables

### Steps

```bash
# 1. Clone or download this folder
git clone https://github.com/YOUR_USERNAME/binance-agentic-tg-bot.git
cd binance-agentic-tg-bot

# 2. Install dependencies
npm ci

# 3. Configure environment
cp .env.example .env
# Edit .env and fill in all required values

# 4. Set up the database (run once)
psql "$SUPABASE_DB_URL" -f schema.sql
# OR paste schema.sql into the Supabase SQL Editor

# 5. Build
npm run build

# 6. Start
npm start
```

The bot starts long-polling and the health check listens on `http://localhost:3000/health`.

### Development (hot-reload with ts-node)

```bash
npm run dev
```

## Database Setup

Run `schema.sql` once against your PostgreSQL/Supabase database. It creates two tables:

- **`users`** — one row per Telegram user, tracks wallet connection state and completed job count
- **`executions`** — one row per pipeline run, stores all transaction hashes, amounts, P&L, and agent ID

The bot also runs `CREATE TABLE IF NOT EXISTS` on startup via `initDb()`, so a manual schema run is optional but recommended (the SQL file also creates performance indexes that `initDb()` does not).

## Deployment

### Railway (recommended)

```bash
# Install Railway CLI
npm install -g @railway/cli

# Login and deploy
railway login
railway init
railway up

# Set environment variables (or use the Railway dashboard Variables tab)
railway variables set GEMINI_API_KEY="your_key"
railway variables set TELEGRAM_BOT_TOKEN="your_token"
railway variables set SUPABASE_DB_URL="your_connection_string"
railway variables set ADMIN_ID="123456789"
railway variables set BSC_RPC_URL="https://bsc-dataseed1.binance.org/"
```

Railway auto-detects `nixpacks.toml` / `railway.toml` and uses:
- **Build:** `npm ci --omit=dev && npx tsc`
- **Start:** `node dist/index.js`
- **Health check:** `GET /health` → `{"status":"ok","uptime":...}`

### Render

1. Connect your GitHub repository in the Render dashboard.
2. Set **Build Command:** `npm ci && npm run build`
3. Set **Start Command:** `node dist/index.js`
4. Add all environment variables in the Render Environment tab.
5. Set **Health Check Path:** `/health`

### GitHub Upload (drag-and-drop)

Upload only the contents of this folder — **do not include `node_modules/` or `dist/`**. GitHub will store the source; Railway/Render will run `npm ci` and `tsc` during the build step.

```
✅ Upload:  src/  schema.sql  package.json  package-lock.json
            tsconfig.json  railway.toml  nixpacks.toml
            .env.example  .gitignore  README.md

❌ Do NOT upload:  node_modules/  dist/  .env
```

## Binance Agentic Wallet Integration

> ⚠️ Transaction signing requires the official **Binance Agentic Wallet SDK** (not yet publicly released). Until it is available:
> - The bot generates real WalletConnect v2 pairing URIs and QR codes correctly.
> - The `buildSignerFromSession()` function in `src/wallet.ts` throws a clear error with integration instructions.
> - All other bot flows (DB, Gemini, BSC reads, stop-condition checks) work fully.

**To wire the real SDK when available:**

```typescript
// In src/wallet.ts — replace buildSignerFromSession() body:
import { BinanceAgenticWallet } from '@binance/wallet-sdk';
const sdk = new BinanceAgenticWallet({ sessionId: session.sessionId });
return sdk.getSigner(provider);
```

## Bot Commands & Flow

| Trigger | Action |
|---|---|
| `/start` | Save user to DB, show main menu |
| Connect Wallet button | Generate WalletConnect pairing URI + save to session |
| Generate QR Code button | Render pairing URI as scannable QR image |
| Complete All Process button | Run full mint → approve → sell pipeline |
| My Jobs button | Show completed job count and all Agent IDs used |
| Cancel button | Abort running job at next checkpoint, reset session |
| `/admin_users` | *(ADMIN\_ID only)* List all users who sent /start |
| `/admin_completed` | *(ADMIN\_ID only)* List completed users + their Agent IDs |

### Stop Conditions (halt immediately, no further on-chain writes)

| Condition | Check Point |
|---|---|
| BNB balance < mint cost + 0.01 BNB gas buffer | Before mint |
| No SPACE ID AI name (`*.ai`) on wallet | Before mint |
| Developer mode not enabled | Before mint |
| Mint quota exhausted | Before mint |
| Simulated sell proceeds > 8% below mint cost | After mint, before approve |
| User pressed Cancel | Between each step |
| Transaction reverted on-chain | On receipt |

## Security

- 🔒 Never asks for seed phrases or private keys
- 🔒 Never asks users to send BNB directly to any address
- 🔒 All transactions use LOW gas (network base fee × 1.05)
- 🔒 Admin commands are hard-gated to `ADMIN_ID` integer comparison
- 🔒 Per-user execution lock prevents race conditions and double-spending
- 🔒 Mint simulations run before any on-chain write; failed simulations cost zero gas
